# Personal Application 01：Todo、Chat、Note，基础三件套

我想开一个 Personal Application 系列，把自己用的个人应用写成极简的文字说明。不讲代码，主要讲它们管什么，信息怎么流动。写下来，也方便自己想清楚哪些东西该放在一起，哪些不该。

先拿写一篇博客举例。最开始可能只是聊到一个想法，之后找几篇参考文章、讨论大纲、写初稿，再修改。过几天回来，我需要知道的不只是“写完没有”，还有这篇准备讲什么、正文在哪、上次定了什么。

我用 Todo、Chat、Note 把这些信息分开，又关联到一起。它们是这套个人应用的基础三件套。

## 从 Chat 开始，把事情说清楚

有个想法时，我通常先和 agent 聊。不一定马上知道要交付什么，可能只是觉得某个问题值得想一想。

比如想写一篇介绍个人应用的文章，先讨论读者是谁、讲哪些内容、拿什么举例。等方向清楚，再让 agent 整理大纲、起草正文，我继续给反馈。

所以 Chat 不只是存聊天记录的地方，也是讨论和推进工作的入口。但聊过不等于做完，消息越来越长，也不等于事情越来越清楚。

## 需要持续跟进，就放进 Todo

决定把这个想法写成一篇文章时，就需要一个 Todo。

标题写要做什么，描述写范围，比如“介绍基础模块的分工，不贴代码”。优先级回答先做哪件，状态回答有没有开始、是否完成。进度则留一句接得上的话，比如“初稿已写好，下一步精简例子”。

同一篇文章可能聊不止一次。选题、大纲、修改稿可以在不同的 Chat 里推进，但都关联到同一个 Todo。换了聊天窗口，还是同一件事，不需要重新猜它做到哪了。

Todo 不用装下完整的讨论和正文。它负责让我快速知道：**要做什么，现在到哪，接下来做什么。**

## 形成的内容，留在 Note

大纲和正文需要一个稳定的位置，不能只靠往上翻消息找“最新那版”。这些内容放在 Note 里，再关联到 Todo。

Chat 里可以提出三个方向，再否掉两个。Note 里则留下当前选定的方向、必要的理由和最新正文。后面改了主意，就更新对应内容，而不是让下一次接手的人自己从对话里推断。

一个 Todo 可以关联计划、草稿等多篇 Note。一份应用说明也可以被几个任务共用，不必每次复制背景。任务结束了，文档仍然可以继续使用。

写作时参考的外部文章，可以通过 Link 保留来源，再在 Note 里写下哪些内容值得参考，以及自己的理解。这里分清两件事就够了：**保存链接是留住来源，写 Note 是整理自己要留下的内容。** 收藏本身不等于已经理解，也不意味着必须再建一个 Todo。

## 修改时，结论要写回去

假设我看完初稿，觉得范围太大，在 Chat 里说“这篇先不讲自动化”。这句话不应该只留在聊天里：Todo 的范围要更新，Note 里的正文要删改，进度里留下修改结果和下一步。

需要我审稿或做决定时，Todo 进入 `awaiting`，也就是等我处理；给出反馈后继续做，确认完成后再收尾。

这样，一篇文章从想法到完成的过程就串起来了：在 Chat 里讨论，决定跟进时建 Todo，参考材料保留来源，形成的内容写进 Note，反馈再回到讨论和修改里。

过几天回来，先看 Todo 就知道进度，打开 Note 就能继续改正文。只有想追溯某个决定时，才需要回看 Chat，而不是每次都重读一遍历史消息。

## 分开，但不各管各的

**Chat 推进事情，Todo 跟踪事情，Note 留下内容。** 三者关联起来，才方便从一个想法走到结果，再从结果继续下一件事。

这不代表所有信息都要走完整套流程。随口问一个问题，留在 Chat 就够了；记下一段想法，也可以只有 Note。需要持续推进的事才建 Todo，相关材料再关联过去。

我想保留的不是三份重复记录，而是三种不同的信息：讨论过程、任务现状、可以继续使用的内容。分开放，更新时各归各位，下次就不用从一长串对话里重新拼出整件事。
