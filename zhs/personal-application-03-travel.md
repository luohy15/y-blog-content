# Personal Application 03：Travel，一趟旅行的三个部分

这是 Personal Application 的第三篇。不讲代码，只讲这个应用管什么，信息怎么流动。前两篇是 Todo、Chat、Note 的基础三件套，然后是 Finance。这一篇是 Travel。

空下来的时候我会打开 Travel，想知道两件事：今年去了哪些地方，某一趟又是什么。列表回答第一个，详情页回答第二个。计划和游记不在这两个页面上，它们是 note，靠同一个 tag 找回来。

## 行程列表

列表里是我记下的每一趟，一趟一行。名字、日期、几天几晚、同行的人，最后一列是净花费。按年份筛一下，这一年去了哪里、每趟大概花了多少，一眼就能看到。

净花费不是我自己填的，是那趟的成本查询对每一行各跑一遍。不用点开一趟，也能看到它的数。

排序可以按开始日期或者净花费。筛选条件里还有时长、境内境外、同行的人和目的。状态也是上面的筛选，不是行里的一列。

## 基础信息

详情页先给事实：日期、几天几晚、境内还是出境、和谁去、为什么去、去了哪里、现在是什么状态。这些字段都是我自己填的，回答的是这趟是什么，不是这趟怎么样。

还有一个 notes 字段，和游记无关。它记的是录入时还不确定的东西：哪些是猜的，哪笔还没记上。它不是成本的来源，时间久了也会过时，所以偶尔会和下面的数字对不上。

页头是名字、状态和 tag。tag 只是一行字，点不开计划，也点不开游记，详情页不会把相关的 note 列在旁边。想找那两篇，得去 Tag 视图里搜同一个 tag。这里有一点可惜：tag 本来正是能把它们串起来的东西。

## 计划和实际

出发前我会写一篇行程 note。路线、已经订好的机票和酒店、逐日的安排，还有下雪或者堵车时的备用方案。为什么这么走、为什么从这边进那边出，也写在同一篇里，因为这部分我忘得最快。

回来以后，实际发生了什么写进游记。哪一天开成了整天的车，哪一段是临时加的，路上在检查站碰到什么。

应用不对照这两份东西。它没有计划字段，也没有实际字段，行程记录里只有日期和目的地。计划在计划那篇里，实际在游记那篇里，差别要我自己读出来。

tag 能把这两篇连起来，前提是我写了它们。很多行程只有一行记录和一笔钱，出发前没有计划，回来也没有游记。

## 成本

成本块通过 tag 读账本。毛额是这趟相关的支出，offset 是负数的那几笔：同伴转回来一部分，或者订了又退。两者相减就是净额。

## 一个 tag，三个部分

行程这一行是锚。计划写在出发前，游记写在回来以后，两篇都是 note。成本不是记录的一部分，每次打开页面，它是对账本的一次查询。这几样东西共有的，只有那个 tag。

**记录留下事实，note 留下计划和游记，成本从账本里读。**

记录薄不是图省事。把总额存进去，或者手写一份逐日经过，都只是多一份要维护的副本，早晚会和账本对不上。现在这样，行程只管它能确定的那几件事，其余的照旧留在 note 和账本里。
